# SC-Audit

智能合约安全审计框架（Smart Contract Security Audit Framework）

## 项目简介

`SC-Audit` 是一个面向智能合约安全分析与风险识别的审计框架，用于系统化梳理链上项目面临的主要安全威胁、结构性风险与新型演进风险。

本项目聚焦于以下目标：

- 建立清晰的智能合约安全风险知识树
- 总结常见漏洞的攻击原理、真实案例与防御方式
- 帮助审计人员、开发者与研究者快速理解 Web3 安全风险全景
- 为安全审计、风险建模、培训与研究提供基础框架

---

## 风险总览

### 根节点：智能合约安全风险

智能合约安全风险可分为三大层次：

1. **已知代码漏洞**
2. **系统级结构性风险**
3. **演进级新型风险**

---

## 一、已知代码漏洞

这一层主要关注传统意义上的合约代码缺陷，通常可以通过代码审计、测试、静态分析与最佳实践进行识别和缓解。

### 1.1 重入攻击（Reentrancy）

- **原理**：转账前未更新状态，攻击者可通过递归回调反复进入目标函数。
- **案例**：2016 年 The DAO 事件，损失约 6000 万美元。
- **防御**：
  - 遵循 CEI（Checks-Effects-Interactions）原则
  - 使用 `ReentrancyGuard`

### 1.2 访问控制缺失（Access Control）

- **原理**：关键函数未限制调用权限，导致任意用户可执行敏感操作。
- **案例**：2022 年访问控制问题占安全损失约 40%。
- **防御**：
  - 使用 `onlyOwner`
  - 引入 RBAC（基于角色的访问控制）
  - 禁用 `tx.origin` 作为鉴权依据

### 1.3 闪电贷攻击（Flash Loan Attack）

- **原理**：攻击者零成本借入巨额资金，在单笔交易内放大其他漏洞影响。
- **案例**：Cream Finance 攻击事件，损失约 1.3 亿美元，并伴随价格操纵。
- **防御**：
  - 使用 Chainlink 预言机
  - 使用 TWAP（时间加权平均价格）

### 1.4 整数溢出 / 下溢（Overflow / Underflow）

- **原理**：数值运算超出类型范围，导致归零或变为极大值。
- **案例**：在 Solidity 0.8 之前广泛存在。
- **防御**：
  - 使用 Solidity 0.8+
  - 谨慎使用 `unchecked {}`

### 1.5 随机数可预测（Predictable Randomness）

- **原理**：链上状态公开透明，不存在真正安全的原生随机数。
- **案例**：NFT 抽签、链上抽奖等场景被操纵。
- **防御**：
  - 使用 Chainlink VRF

### 1.6 价格操纵（Price Manipulation）

- **原理**：直接读取 DEX 瞬时价格，容易被短时砸盘或拉盘操控。
- **案例**：多个借贷协议遭受套利与攻击。
- **防御**：
  - 使用 TWAP
  - 接入 Chainlink 等去中心化预言机

### 1.7 签名重放（Signature Replay）

- **原理**：同一签名可在不同合约或不同链上被重复使用。
- **案例**：跨链协议中签名被复用。
- **防御**：
  - 使用 EIP-712
  - 在签名中包含 `nonce` 与 `chainId`

### 1.8 Delegatecall 存储错位

- **原理**：代理升级时存储槽布局不一致，导致状态变量错位与安全问题。
- **案例**：2022 年 Nomad Bridge 事件，损失约 1.9 亿美元。
- **防御**：
  - 严格对齐存储布局
  - 使用 UUPS / Transparent Proxy 等成熟升级方案

### 1.9 前端运行（Front-Running）

- **原理**：攻击者在 mempool 观察到交易后，抢先插入交易获利。
- **案例**：DEX 三明治攻击，每年损失规模超过 6 亿美元。
- **防御**：
  - 设置最大滑点保护
  - 使用 Flashbots 私有 mempool

### 1.10 Gas 耗尽 DoS

- **原理**：循环长度由用户控制，攻击者可构造超大输入使交易耗尽 Gas。
- **案例**：奖励分发合约中被塞入大量地址，导致执行失败。
- **防御**：
  - 设置数组长度上限
  - 分页处理大规模数据

## 二、系统级结构性风险

这一层风险并不总是来自单点代码漏洞，而是来自协议设计、组合方式、经济机制与外部依赖。

### 2.1 可组合性涌现风险

- **原理**：各合约单独看似安全，但组合后可能产生新的攻击面。
- **案例**：2022 年 Cream Finance 攻击事件，ERC-20 借贷逻辑与 ERC-777 转账钩子组合后引发重入。
- **机制**：
  - ERC-20 借贷逻辑正常运行
  - ERC-777 转账时触发钩子
  - 钩子中发生重入，绕过借款记录
- **防御**：
  - 审计所有外部代币标准兼容性
  - 关注协议间交互引入的隐式状态变化

### 2.2 经济模型 / 博弈论漏洞

- **原理**：代码本身没有错误，但在理性参与者行为下，系统仍可能崩溃。
- **典型类型与案例**：

#### 死亡螺旋

- **案例**：2022 年 Luna / UST 崩盘，损失约 400 亿美元。
- **机制**：做空触发恐慌，用户理性出逃，系统最终归零。

#### 清算失效

- **案例**：2020 年 MakerDAO Black Thursday，约 400 万美元资产被零价清算。
- **机制**：Gas 费用过高、竞争风险过大，导致无人清算，坏账持续堆积。

#### 流动性挤兑（Bank Run）

- **案例**：多个借贷协议均曾面临类似风险。
- **机制**：传言或风险预期出现后，先退出者获利，最终导致集体出逃和系统崩溃。

#### 治理攻击

- **案例**：2022 年 Beanstalk 攻击事件，损失约 1.82 亿美元。
- **机制**：攻击者通过闪电贷借入治理代币，短时间内获得多数投票权，并在 13 秒内通过恶意提案。

- **防御**：
  - 将投票快照与即时余额分离
  - 设置时间锁（Timelock）
  - 对经济模型进行压力测试与极端情境推演

### 2.3 外部依赖风险

- **原理**：系统的安全上限取决于最弱的外部依赖。
- **案例**：
  - Nomad Bridge：升级时将验证根设为空值，导致任何消息都可通过验证，损失约 1.9 亿美元
  - Circle 冻结 USDC：中心化稳定币可能受到监管干预
  - 跨链桥被攻击：桥接资产失去支撑，锁定价值归零
- **防御**：
  - 使用多源依赖
  - 设置限额与熔断机制
  - 避免单点信任

## 三、演进级新型风险

这一层风险来自新架构、新基础设施与新开发方式，具有更强的前沿性与不确定性。

### 3.1 MEV（矿工 / 验证者可提取价值）

- **原理**：验证者或相关参与者可通过重排交易顺序，从普通用户交易中提取利润。
- **案例**：三明治攻击
- **攻击流程**：
  - 机器人发现用户在 DEX 发起交易
  - 先抢跑买入推高价格
  - 用户以更差价格成交
  - 机器人随后卖出套利
- **现象**：以太坊生态每年被提取价值超过 6 亿美元。
- **防御**：
  - 设置滑点保护
  - 使用 Flashbots 私有 mempool

### 3.2 账户抽象（ERC-4337）新攻击面

- **原理**：账户抽象引入了 Paymaster、Bundler 等新角色，带来新的信任边界与攻击面。
- **案例**：恶意 Paymaster
- **攻击方式**：
  - 表面上为用户代付 Gas
  - 实际在同一笔交易中转走用户已授权代币
- **防御**：
  - 严格审计 Paymaster 合约
  - 采用最小授权原则

### 3.3 ZK 电路漏洞

- **原理**：零知识证明中的数学约束写错，会导致链上验证逻辑失效。
- **案例**：2023 年 zkSync 白帽发现问题。
- **示例**：
  - 将约束条件 `> 0` 误写为 `>= 0`
  - 攻击者可能借此凭空增发代币
- **特点**：
  - 传统智能合约分析工具如 Slither 对此类问题往往无效
- **防御**：
  - 开展专项 ZK 电路审计
  - 使用形式化验证方法

### 3.4 AI 生成代码隐患

- **原理**：AI 可能复用过时代码模式，且无法真正理解业务上下文。
- **案例**：质押合约溢出漏洞
- **机制**：
  - AI 生成了 2019 年的旧代码模式
  - 新协议允许治理将 `rewardRate` 调整到极大值
  - 结果发生溢出，导致奖励异常放大
- **防御**：
  - AI 生成代码必须经过人工安全审查
  - 禁止未经审计直接上线

## 审计建议

在实际审计中，应避免只关注“代码层漏洞”，而忽视协议整体安全性。建议从以下三个维度同时开展评估：

- **代码安全**：重入、权限控制、算术、签名、升级代理等
- **协议安全**：组合性、经济模型、治理机制、清算设计等
- **生态安全**：预言机、跨链桥、稳定币、AA、ZK、MEV 等外部因素
